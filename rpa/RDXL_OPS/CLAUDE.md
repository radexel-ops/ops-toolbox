# VibeOps - AI-First 운영 자동화 플랫폼 Master Protocol

**프로젝트명**: VibeOps (경영기획팀 주도 AI-First 운영 자동화 플랫폼)

> **Claude Code 지침**: 이 문서는 프로젝트의 '헌법'입니다. 모든 작업 시 이 문서의 원칙을 최우선으로 적용하고, `knowledge/` 폴더의 세부 사항을 참조하십시오.

## 0. 최고 원칙 (Supreme Directives) — 모든 에이전트 필독

> **이 섹션은 프로젝트의 최상위 지침입니다. 다른 모든 섹션보다 우선하며, 모든 에이전트가 반드시 준수해야 합니다.**

### 0.1 프로젝트 목표 (Project Goals) — NON-NEGOTIABLE

1. **개발팀 의존 탈피**: 경영기획팀이 직접 서버/DB를 구축하고 유지보수 가능한 환경
2. **대화형 개발**: 웹 인터페이스를 통해 Claude Code와 대화하며 실시간 업무 도구 개발
3. **1인 1 AI 에이전트**: 향후 전 임직원에게 개인화된 업무 자동화 환경 제공

### 0.2 컨텍스트 전달 의무 (Context Propagation) — NON-NEGOTIABLE

* **모든 하위 에이전트에게 이 프로젝트의 지침과 지식을 반드시 전달하십시오.**
* 하위 에이전트는 `CLAUDE.md`의 원칙, `knowledge/` 폴더의 아키텍처를 이해한 상태에서 작업해야 합니다.
* **지침 없이 코드만 던지는 위임은 금지합니다.** 맥락 없는 위임 = 기술부채.

### 0.3 7대 원칙 (The Seven Commandments)

| # | 원칙 | 설명 |
|---|------|------|
| **1** | **비개발자 친화적** | 경영기획팀이 직접 운영/확장할 수 있어야 한다. 복잡한 설정보다 직관적인 인터페이스 우선. |
| **2** | **기술부채 제로** | 깔끔하고 유지보수 가능한 코드만 허용. 임시방편 금지. |
| **3** | **모듈 재사용 의무** | 코드 작성 전 `knowledge/09_MODULE_REGISTRY.md`를 확인. 중복 구현 금지. |
| **4** | **보안 최우선** | 인증, 권한, 데이터 보호는 타협 없이 완벽하게. 더존/사내 시스템 연동 시 특히 주의. |
| **5** | **UX/UI 일관성** | 전체 서비스와의 시각적·경험적 일관성 유지. Modern, Clean, Professional. |
| **6** | **심플함이 최고** | 많은 기능 ≠ 좋은 서비스. 사용자에게 보이는 것은 극도로 직관적이어야 함. |
| **7** | **확장 가능한 설계** | 새로운 에이전트/기능 추가가 쉬워야 함. 플러그인 아키텍처 지향. |

### 0.4 에이전트 위임 시 필수 포함 사항

하위 에이전트(Task tool)를 생성할 때 프롬프트에 **반드시** 다음을 포함:

```
1. 이 프로젝트는 VibeOps(AI 운영 자동화 플랫폼)이다. CLAUDE.md의 7대 원칙을 준수할 것.
2. 코드 작성 전 knowledge/09_MODULE_REGISTRY.md를 확인하여 기존 모듈을 재사용할 것.
3. 비개발자(경영기획팀)도 이해하고 운영할 수 있는 수준의 코드를 작성할 것.
4. 네가 맡은 작업이 전체 서비스에서 어떤 역할인지: [구체적 설명]
```

## 1. 핵심 철학 (Core Philosophy)

### 1.1 AI 자율성 (AI Autonomy)

* **Human = WHAT (의도 전달)**: 사용자는 "무엇"을 원하는지만 정의합니다.
* **AI = HOW (실행 판단)**: "어떻게" 할지는 AI가 자율적으로 판단합니다.
* **최적 제안**: 시스템은 항상 최적의 자동화된 경로를 제안할 역량이 있어야 합니다.

### 1.2 "외부는 심플, 내부는 디테일"

* **보이는 것**: 사용자는 복잡성을 알 필요가 없습니다. UI는 극도로 직관적이어야 합니다.
* **감춰진 것**: 내부는 디테일해야 합니다. 에러 핸들링, 재시도, 예외 처리는 완벽해야 하지만, 사용자 눈에는 보이지 않게.

### 1.3 대화형 개발 (Conversational Development)

* **웹에서 명령 → 서버에서 실행**: 웹 대시보드 채팅으로 명령하면 서버의 Claude Code가 실행
* **실시간 피드백**: 작업 진행 상황과 결과를 실시간으로 웹에 표시
* **점진적 확장**: 새로운 기능은 대화를 통해 즉석에서 개발 가능

## 2. 시스템 아키텍처 개요 (Architecture Overview)

### 2.1 인프라

| 구성 요소 | 기술 | 설명 |
|----------|------|------|
| **서버** | DigitalOcean Droplet (Ubuntu 24.04) | 가상 PC 환경, 8GB RAM 이상 권장 |
| **데이터베이스** | SQLite | 파일 기반, 백업/이동 용이, Claude Code 직접 제어 가능 |
| **프로세스 관리** | Tmux | AI 에이전트 팀의 '사무실', 멀티 세션 관리 |
| **웹 프레임워크** | FastAPI | Python 비동기, 자동 API 문서 |

## 3. UX/UI 원칙 (Design Principles)

**스타일: "Modern, Professional, Clean"**

* **심플함의 극치**: 불필요한 장식 제거. 정보의 계층 구조 명확화.
* **미적 기준**: 모던하고 세련된 기업용 웹 디자인. 명확한 대비와 깊이감.
* **직관성**: 설명서가 필요 없는 UI. 경영기획팀이 바로 사용 가능해야 함.

## 4. 엔지니어링 표준 (Engineering Standards)

### 4.1 기술 스택

| 영역 | 기술 | 이유 |
|------|------|------|
| **Backend** | FastAPI (Python 3.11+) | 비동기, 타입힌트, 자동 문서화 |
| **Frontend** | HTML/CSS/JS (Vanilla 또는 Vue.js) | 경량, 빠른 로딩, 유지보수 용이 |
| **Database** | SQLite | 파일 기반, 별도 서버 불필요, 백업 용이 |
| **Process** | Tmux + Systemd | 세션 관리, 서비스 자동 시작 |
| **Automation** | Selenium/Playwright | 더존 등 웹 자동화 |
