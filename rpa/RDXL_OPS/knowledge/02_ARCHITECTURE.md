## 2. 컴포넌트 상세

### 2.1 Frontend (Web Dashboard)

| 컴포넌트 | 기술 | 역할 |
|----------|------|------|
| 채팅 UI | WebSocket | Claude Code와 실시간 대화 |
| 대시보드 | REST API | 시스템 상태, 통계 표시 |
| 에이전트 관리 | REST API | 에이전트 시작/중지/설정 |
| 설정 | REST API | 사용자 설정, 시스템 설정 |

### 2.2 Backend (FastAPI)

```python
# 라우터 구조
app/
├── routers/
│   ├── auth.py        # 인증 (로그인, 세션)
│   ├── bridge.py      # 브릿지 (WebSocket 연결)
│   ├── agents.py      # 에이전트 관리
│   ├── tasks.py       # 작업 관리
│   └── monitor.py     # 모니터링
├── services/
│   ├── auth_service.py
│   ├── bridge_service.py
│   ├── agent_service.py
│   └── database_service.py
└── models/
    ├── user.py
    ├── agent.py
    └── task.py
```

### 2.3 Bridge System

```
웹 브라우저                    서버
    │                           │
```

### 2.4 Tmux Session Structure

```
vibeops (Session)
├── 0: pm-agent (Window)      # PM 에이전트 - 작업 분배
│   └── 0: main (Pane)        # Claude Code 대기
│
├── 1: douzone-agent (Window) # 더존 에이전트
│   └── 0: main (Pane)        # 더존 자동화 스크립트
│
├── 2: news-agent (Window)    # 뉴스 에이전트
│   └── 0: main (Pane)        # 뉴스 스크래핑 스크립트
│
└── N: custom-agent (Window)  # 추가 에이전트
    └── 0: main (Pane)
```

## 3. 데이터 흐름

### 3.1 대화형 명령 흐름

```
1. 사용자가 웹 채팅에 입력: "이번 주 야근자 명단 뽑아줘"
   │
   ▼
2. Frontend → Backend: WebSocket 메시지 전송
   │
   ▼
3. Bridge Service: 명령 파싱 및 큐 등록
   │
   ▼
4. Tmux PM Agent 세션에 명령 전달
   │
   ▼
5. Claude Code가 명령 해석
   ├─ 직접 처리 가능 → 바로 실행
   └─ 전문 에이전트 필요 → 해당 에이전트에 위임
   │
   ▼
6. 결과 생성 (데이터, 표, 파일 등)
   │
   ▼
7. Bridge Service → Frontend: 결과 스트리밍
   │
   ▼
8. 웹 UI에 결과 렌더링
```

### 3.2 스케줄 작업 흐름

```
1. Cron/Scheduler: 정해진 시간에 트리거
   │
   ▼
2. Agent Service: 해당 에이전트 활성화
   │
   ▼
3. Tmux 세션에서 스크립트 실행
   │
   ▼
4. 작업 완료 → 결과 저장
   │
   ▼
5. 알림 발송 (Slack, 웹 대시보드)
```
